# Telegram Inline Keyboard Styler Bot

بوت Telegram مكتوب بـPython لمعالجة ملفات مصدر `.py` و`.php` التي تحتوي على تعريفات يُحتمل أن تكون أزرار Inline Keyboard. يحاول تحليل الملف واستخراج الأزرار المرشحة، ثم يعرضها للمستخدم واحدًا تلو الآخر لاختيار نمط، مع إمكانية المعاينة والتخطي والعودة. تُطبّق التعديلات على نسخة العمل المحفوظة محليًا على مضيف البوت.

> **تنبيه حول نطاق الوظيفة:** التحليل ساكن واستدلالي وليس محللًا كاملًا للغتي Python أو PHP، لذا قد لا يكتشف كل الأزرار أو قد يحدد مقاطع غير مقصودة. راجع المعاينة والتغييرات قبل استخدام أي ملف ناتج.

## الميزات الظاهرة في المصدر

- استقبال ملفات مصدر وتحليلها لاستخراج تعريفات أزرار محتملة:
  - يستخدم تحليل AST في Python، مع تعبيرات نمطية احتياطية عند الحاجة.
  - يعتمد على أنماط نصية وتعبيرات نمطية في PHP.
- اختيار أحد الأنماط المعروضة لكل مرشح: `success` أو `danger` أو `primary` أو `warning` أو `secondary`.
- معاينة الفرق بين النسخة الأصلية والتعديلات، وتخطي مرشح أو الرجوع وإعادة الاختيار.
- حفظ جلسات العمل وحالتها في SQLite، وإعادة بناء الملف المعدل انطلاقًا من نسخة احتياطية داخلية.
- أوامر البوت: `/start` و`/resume` و`/cancel` و`/status`.

## المتطلبات

- Python وتبعياته المحددة في `requirements.txt`؛ التبعية المذكورة هناك هي `python-telegram-bot` ضمن المجال المحدد في ذلك الملف.
- رمز بوت Telegram مضبوط في متغير البيئة `BOT_TOKEN`.
- PHP ليس مدرجًا ضمن التبعيات المطلوبة. إذا كان متاحًا على المضيف، يحاول المصدر استخدام `php -l` لفحص صياغة الملف بعد التعديل؛ وإلا يستخدم فحوصًا بنيوية محدودة.

لم يحدد المستودع إصدار Python أدنى، ولا يوفّر ملف إعداد نشر أو ملفات اختبار. لا توجد في المستودع تعليمات مثبتة للتشغيل في الإنتاج.

## الإعداد والتشغيل

الخطوات أدناه مستندة إلى `requirements.txt` ونقطة الدخول `main.py`، لكنها **غير مجرّبة** ضمن هذه المراجعة:

1. أنشئ بيئة Python مناسبة للمضيف وثبّت المتطلبات:

   ```bash
   python -m pip install -r requirements.txt
   ```

2. أضف `BOT_TOKEN` إلى بيئة التشغيل أو إلى مخزن أسرار آمن. لا تضع الرمز في الشيفرة أو المستودع أو السجلات.
3. شغّل نقطة الدخول:

   ```bash
   python main.py
   ```

يستخدم التطبيق Telegram polling. عند بدء التشغيل ينشئ مساحة العمل وقاعدة البيانات عند الحاجة. لم يتم التحقق من نجاح التثبيت أو التشغيل، ولا تتضمن هذه التعليمات إعداد خدمة دائمة أو نشرًا إنتاجيًا.

## الإعدادات والتخزين

يعرف المصدر متغيرات البيئة التالية:

- `BOT_TOKEN` — مطلوب للمصادقة مع Telegram.
- `BOT_WORKDIR` — يحدد جذر مساحة العمل التي تحفظ فيها الملفات والجلسات.
- `MAX_FILE_SIZE_MB` — معرّف في المصدر كإعداد للحجم، لكن لا يظهر استخدامه في مسار التحقق من الملفات؛ لذلك لا تفترض أن حدًا أقصى للحجم مفروض فعليًا.
- `LOG_LEVEL` — مستوى التسجيل.

تحتوي مساحة العمل على ملفات المستخدم والنسخ الاحتياطية، كما تُنشأ قاعدة SQLite للجلسات. لا يظهر في المصدر إجراء تنظيف تلقائي أو مدة احتفاظ أو أمر لحذف هذه الملفات والسجلات؛ خطط لإدارتها يدويًا وفق سياسة مناسبة قبل الاستخدام الفعلي. بعد الإنهاء، يخبر البوت المستخدم بأن النسخة المعدلة محفوظة على مضيف البوت؛ لا يظهر في المصدر مسار يرسل الملف الناتج إلى المستخدم كمرفق.

## حدود معروفة

- الاستخراج قائم على AST/التعبيرات النمطية وأنماط محددة في المصدر؛ لا يضمن فهم كل تنويعات الشيفرة أو سلامة التعديل لكل ملف.
- فحص PHP بـ`php -l` اختياري بحسب توفر PHP، وهو فحص صياغة وليس اختبارًا وظيفيًا للبرنامج الأصلي.
- لا توجد اختبارات أو آلية موثقة لإثبات صحة الملفات المعدلة، ولا سياسة احتفاظ أو حذف موثقة.
- المصدر ينشئ مسار الملف من اسم الملف الوارد؛ يلزم التحقق من أسماء الملفات وعزل مساحة العمل قبل معالجة ملفات غير موثوقة.
- ملف الاعتماديات يسرد تبعية واحدة فقط، ولا يتضمن المشروع ملفات إعداد نشر أو إعداد حاويات.

## تنبيه أمني وخصوصية

تعامل مع الملفات المرسلة على أنها غير موثوقة وقد تتضمن شيفرة أو بيانات حساسة. تُنقل الملفات عبر Telegram وتُحفظ نسخ منها وقاعدة الجلسات على مضيف البوت؛ لا ترسل ملفات لا تملك صلاحية مشاركتها، واحمِ مساحة العمل وملف قاعدة البيانات ونسخها الاحتياطية من الوصول غير المصرح به. استخدم رمز البوت عبر مخزن أسرار، وقيّد صلاحيات المضيف، ونفّذ مراجعة مستقلة لعزل الملفات وتنظيف الأسماء وسياسة الحذف قبل التشغيل العام. لا تعتبر البوت بيئة تنفيذ أو معالجة آمنة للملفات لمجرد أنه يفحص الصياغة.
